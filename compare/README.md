# compare/ — what this costs, and what it costs against the alternatives

> **`compare/` or `bench/`?** The names are synonyms; the split is not.
>
> - **`compare/` (here)** measures gwag and gat *against other tools*.
> - **[`bench/`](../bench)** measures gwag *against itself* — throughput
>   on your hardware, knee detection, profiles. Output:
>   [`docs/perf.md`](../docs/perf.md). Driven by `bin/bench`.
>
> This directory drives its sweeps with `bench/cmd/traffic`, so the
> load generator is shared and the numbers are directly comparable.

Two harnesses, two questions:

- **Gateway comparison** — gwag and gat vs Hive Gateway, graphql-mesh
  (v0), Apollo Router, WunderGraph Cosmo and Grafbase, process to process, against the same `hello-proto`,
  `hello-openapi`, `hello-graphql` backends. Each gateway runs its own
  sweep in turn (serial, single-process).
- **[`gatbench/`](./gatbench)** — what gat's abstraction costs against
  writing each surface by hand: gqlgen, connect-go, grpc-gateway.
  In-process microbenchmarks, no network.

`docs/perf.md` is the third view: gwag's own throughput sweep on your
hardware.

- **grpc-gateway** — proto service + REST transcoding, in-process

#### Reading these tables

The peer is the hand-written implementation of the same surface,
speaking the same wire format: grpc-gateway for REST, connect-go for
gRPC, gqlgen for GraphQL.

- **gat / REST is huma, unmodified.** `gat.Register` calls
  `huma.Register` and captures a handler reference; it adds nothing to
  the REST path. That row compares huma's router against
  grpc-gateway's transcoder — useful, but it is not measuring gat.
- **The main table's gRPC row uses the binary codec**, which is what
  grpc-go and connect-go clients speak. The JSON codec costs both
  implementations substantially more; see the per-caller table.
- **gRPC proper (`application/grpc+proto`) is not measured here.** It
  needs HTTP/2, which an `httptest.ResponseRecorder` cannot provide,
  and standing up an h2c server would add a loopback round trip larger
  than the difference under test. It shares the binary codec path with
  the Connect-proto rows, plus HTTP/2 framing.
- **gqlgen runs with its query cache on**, as its own recommended
  server does, so neither GraphQL row re-parses per request.

## Layout

```
compare/
  Dockerfile               ubuntu:26.04 + Go + Node + each gateway binary
  competitors.yaml         declarative list of gateways to test
  cmd/compare/             Go orchestrator (boots backends, sweeps each gateway)
  cmd/gat-gateway/         gat fronting the same upstreams, for the gat row
  configs/
    hive/                  Hive Gateway (Mesh v1 compose) config
    mesh/                  graphql-mesh v0 config
    apollo/                Apollo Router config
    cosmo/                 WunderGraph Cosmo Router config
    grafbase/              Grafbase Gateway config
  scripts/start-*.sh       per-gateway boot/stop
  run.sh                   container entrypoint
  sync-readme.py           splices comparison.md's headline into this file
  gatbench/                separate Go module: gat vs gqlgen / connect-go / grpc-gateway
```

Status: gwag, gat, Hive Gateway and graphql-mesh wired for every
scenario they support; Apollo Router, Cosmo and Grafbase in
single-subgraph mode against `hello-graphql`. gat sits out the `graphql` scenario — ingesting a
downstream GraphQL service is a full-gwag feature. Current numbers:
[`comparison.md`](./comparison.md).

## How to run

Docker (hermetic):
```bash
docker build -t gwag-compare -f compare/Dockerfile .
docker run --rm \
  -v $(pwd)/compare/.out:/out \
  -e HOST_UID=$(id -u) -e HOST_GID=$(id -g) \
  gwag-compare
```

Host-local (faster iteration; needs the bench stack down):
```bash
bin/bench down                       # frees :18080 + :50090
compare/run.sh local
compare/run.sh local --only gwag        # debug: one gateway
```

## Caveats

- **Apollo Router, Cosmo and Grafbase are GraphQL-federation specialists.**
  They appear here in single-subgraph mode (forwarding to
  `hello-graphql`) — the closest apples-to-apples row for a
  GraphQL-in / GraphQL-out cost.
- **Hive Gateway and graphql-mesh are the closest peers** on
  multi-format ingest. Hive runs one worker per core.
- **Numbers reflect this host's hardware**, not absolute speed. The
  load generator, the backends and the gateway share the host's
  cores, so on a small host a gateway that spends less CPU per
  request gains ground. Do not assume the ordering carries to a
  host with a different core count.
- **First Docker build pulls ~1 GB** (Go + Node + Apollo binary +
  npm tree); allow 5–10 minutes. If `graphql-mesh` or `Apollo
  Router` versions drift, pin in `configs/mesh/package.json` or
  bump `APOLLO_VERSION` in `scripts/start-apollo.sh` + `Dockerfile`.
